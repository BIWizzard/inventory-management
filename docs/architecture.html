Architecture overview

Factory Inventory Management System

A two-tier demo app: a Vue 3 single-page app talks to a FastAPI service over JSON. There is no database — the backend loads a set of JSON files into memory at startup and filters them per request.

System architecture

Two processes on localhost. The browser loads the SPA from Vite on port 3000; the SPA calls the API on port 8001 directly (CORS is open, no dev proxy). All state on the server is read-only module-level data.

Tech stack

Deliberately small. No UI kit, no charting library, no state-management library, no i18n library — charts are hand-built SVG and shared state lives in composables.

Data flow: a filtered request

The four global filters (Time Period, Warehouse, Category, Order Status) drive almost every screen. This is what happens when a user changes one on the Dashboard.

  1. User changes a filter in the header FilterBar. It writes to a ref that lives at module scope in useFilters, so every view shares one copy. components/FilterBar.vue → composables/useFilters.js
  2. The active view has a watch() on the four filter refs and reloads. getCurrentFilters() renames UI terms to API terms: Location → warehouse, Period → month. views/Dashboard.vue
  3. api.js builds a query string, skipping any filter set to all, and issues an Axios GET to http://localhost:8001/api/…. client/src/api.js
  4. The FastAPI handler runs apply_filters (exact warehouse match; case-insensitive category and status), then filter_by_month for orders. server/main.py
  5. Month filtering accepts YYYY-MM or a quarter key like Q3-2025, expanded via QUARTER_MAP and matched as a substring of order_date. server/main.py · filter_by_month
  6. List endpoints serialize through a Pydantic response_model; summary, spending, and report endpoints return plain dicts computed on the fly. server/main.py
  7. The view stores raw arrays in refs (allOrders, inventoryItems) and derives KPIs, chart geometry, and localized currency in computed properties. views/*.vue, useI18n.js, utils/currency.js

Gaps & caveats

Things found while tracing the code that are worth knowing before changing it.

Client calls endpoints the server doesn't have

api.js defines /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders, but main.py implements neither. App.vue's task loading fails and is caught with a console.error, so only the hardcoded mock tasks appear.

Backlog view is orphaned

views/Backlog.vue exists but isn't registered in the router or nav; backlog data surfaces only through the Dashboard.

Reports bypasses the API client

Reports.vue imports Axios and hardcodes http://localhost:8001 instead of going through api.js. The base URL is also hardcoded in api.js; there's no env-based configuration.

Time logic is pinned to 2025

QUARTER_MAP and the quarterly report bucket only 2025 months. Orders from other years are silently skipped by the quarterly report.

Dashboard backlog count ignores filters

total_backlog_items in /api/dashboard/summary is always the full backlog length, even when other KPIs are filtered.

Demo-grade auth and CORS

useAuth returns a hardcoded mock user, and CORS allows every origin with credentials. Fine for a local demo, not for deployment.
